# spi

Блокирующий мастер-транспорт SPI на LL с **ограниченными ожиданиями** —
симметричен модулю `i2c/`. Полная замена примитивов проектного `MCU/spi.c`:
сигнатуры `SPI_SendData` / `SPI_ReceiveData` те же, поэтому библиотеки на слое
макросов-констант (`max31856`, `eeprom_mc25lc128`) работают с ним без правок.

## Зачем

Примитивы из примера крутятся в вечном цикле по флагу — если периферия или
чип не отвечает, прошивка виснет. Здесь ожидание каждого флага ограничено
(`SPI_TIMEOUT` итераций), а срабатывание таймаута защёлкивается в липкий флаг
ошибки: чтение возвращает `0`, и проверки типа `MAX31856_probe()`
(запись-чтение шаблона) громко проваливаются вместо зависания.

## Функции

```c
void SPI_MasterStart(SPI_TypeDef* spi);   // Enable + CSTART (обязателен на H7!)
void SPI_SendData(SPI_TypeDef* spi, uint8_t data);
uint8_t SPI_ReceiveData(SPI_TypeDef* spi);
uint8_t SPI_TransferData(SPI_TypeDef* spi, uint8_t data);  // send + receive
SPI_Status SPI_GetError(void);            // липкий флаг таймаута
void SPI_ClearError(void);
```

## Использование

```c
/* инициализация SPI (LL_SPI_Init с mode 1, MSB first, soft NSS) - в проекте */
SPI_MasterStart(MAX31856_SPI);  // без CSTART мастер H7 не тактирует шину

if (MAX31856_probe() != MAX31856_OK || SPI_GetError() != SPI_OK) {
    SPI_ClearError();
    /* датчик не отвечает: не запускать опрос, поднять аварию */
}
```

## Замечания

- `SPI_TIMEOUT` — счётчик итераций, не время; переопределяется до включения
  `spi.c` (как `I2C_TIMEOUT` в `i2c/`). При смене тактовой частоты пересмотреть.
- На STM32H7 после `LL_SPI_Enable` мастер молчит, пока не установлен CSTART —
  в примере `cryomm_part` этого вызова нет (инициализация закомментирована),
  `SPI_MasterStart()` закрывает этот нюанс.
- Функции не реентерабельные: несколько задач RTOS на одной шине — мьютекс на
  стороне приложения.
